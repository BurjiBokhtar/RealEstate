# Развёртывание на другом сервере

Приложение целиком настраивается переменными окружения: в коде нет ни одного
адреса конкретного Supabase-проекта. Поэтому «перенести» — значит создать
пустую базу, применить один SQL-файл и подставить четыре строки.

Чего перенос **не** делает сам: данные. Новый Supabase — пустая база. Про
перенос данных — в конце.

---

## Вариант 1. Другой Vercel + другой Supabase

### 1. База

1. Supabase → создать проект.
2. **SQL Editor** → вставить целиком [`supabase/000_full_setup.sql`](supabase/000_full_setup.sql)
   → **Run**. Это таблицы, типы, права, функции, триггеры и bucket `crm-media`
   для фотографий и планов.
3. **Project Settings → API → Exposed schemas** → добавить **`crm`**.
   Без этого шага приложение подключится, но не увидит ни одной таблицы:
   PostgREST отдаёт только те схемы, которые перечислены здесь, а вся программа
   живёт в схеме `crm`, а не в `public`.
4. **Authentication → Sign In / Providers → Allow new users to sign up → OFF.**
   Иначе зарегистрироваться в вашей CRM сможет кто угодно из интернета.

### 2. Ключи

Supabase → **Project Settings → API**:

| Что скопировать | Куда |
| --- | --- |
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` |
| anon / publishable key | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| service_role / secret key | `SUPABASE_SERVICE_ROLE_KEY` |

Все три — из **одного и того же** проекта. Ключ от другого проекта — самая
частая причина того, что вход работает, а создание сотрудников нет.

### 3. Vercel

**Add New → Project → Import** этот репозиторий → **Environment Variables**:

| Переменная | Нужна | Без неё |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | всегда | вместо программы экран «Supabase не настроен» |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | всегда | то же самое |
| `SUPABASE_SERVICE_ROLE_KEY` | для сотрудников и SMS | Настройки → Сотрудники отклоняют всё; рассылка не идёт |
| `CRON_SECRET` | для ночных SMS | каждый ночной запуск отклоняется с 401, молча |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `SMTP_FROM` | по желанию | нельзя отправить договор или чек почтой |

`CRON_SECRET` нигде не берётся — вы придумываете её сами:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Ночные задачи уже описаны в [`vercel.json`](vercel.json) (05:00 UTC) — Vercel
подхватит их сам и сам подставит `CRON_SECRET` в заголовок `Authorization`.

**Deploy.**

### 4. Первый вход

`admin@crm.tj` / `Admin12345` — этот аккаунт создаёт сам SQL-файл.
**Сразу смените пароль** в Настройках: он написан в открытом репозитории.

Остальных сотрудников заводите в Настройки → Сотрудники, роли даёте там же.

## Вариант 2. Свой компьютер как сервер

Это два независимых вопроса: где работает **программа** и где работает **база**.
Их можно решать по отдельности.

### 2A. Программа у себя, Supabase остаётся облачным

Самый простой рабочий вариант: базу и почту для восстановления паролей
по-прежнему держит Supabase, а Next.js крутится у вас.

```bash
npm ci
npm run build
npm run start
```

`.env.local` в корне — те же переменные, что в таблице выше
(шаблон: `.env.local.example`). Нужен Node 20 или новее.

Открыть доступ другим компьютерам в офисе:

```bash
npx next start -H 0.0.0.0 -p 3000
```

и разрешить порт 3000 в брандмауэре Windows. Заходить по `http://IP-компьютера:3000`.

Четыре вещи, которые за вас делал Vercel и теперь придётся сделать руками:

**1. Ночные рассылки.** `vercel.json` вне Vercel не работает вообще. Нужен
планировщик заданий Windows: ежедневно, две задачи —

```bash
curl -X POST -H "Authorization: Bearer ВАШ_CRON_SECRET" http://localhost:3000/api/cron/send-payment-reminders
```

```bash
curl -X POST -H "Authorization: Bearer ВАШ_CRON_SECRET" http://localhost:3000/api/cron/send-task-reminders
```

Заголовок обязателен: без него маршрут отвечает 401 и ничего не отправляет.

**2. Автозапуск.** `npm run start` — обычный процесс: закрыли окно, программа
недоступна. Нужен автозапуск при загрузке компьютера — задание Windows «При
запуске системы», либо `pm2`, либо NSSM (делает из процесса службу Windows).

**3. HTTPS.** По `http://` пароли сотрудников идут по сети открытым текстом.
Внутри офисной сети это терпимо, наружу — нет. Если открываете доступ из
интернета, ставьте перед приложением обратный прокси с сертификатом (Caddy
получает Let's Encrypt сам, без настройки).

**4. Компьютер должен быть всё время включён** и не уходить в сон — иначе
программа недоступна ровно тогда, когда она нужна.

### 2B. Свой ещё и Supabase

Supabase self-hosted — это `docker compose` из репозитория `supabase/supabase`.
Тот же `000_full_setup.sql` применяется точно так же, через SQL-редактор или
`psql`.

Что переходит на вас вместе с этим: резервные копии, свой SMTP (иначе письмо
«восстановить пароль» никуда не уйдёт), обновления, и Docker на машине. Берите
этот вариант, только если облачный Supabase не подходит принципиально —
например, данные нельзя выпускать наружу.

## Перенос данных на новый Supabase

Схема `crm` и учётные записи переносятся **по-разному**.

**Данные CRM** (дома, квартиры, клиенты, договоры, платежи) — это схема `crm`
целиком. Проще всего через `pg_dump` старой базы и восстановление в новую;
строка подключения — Supabase → Project Settings → Database → Connection string.

```bash
pg_dump "СТРОКА_ПОДКЛЮЧЕНИЯ_СТАРОЙ" --schema=crm --data-only --no-owner > crm-data.sql
```

Перед восстановлением новая база должна быть уже создана файлом
`000_full_setup.sql` — иначе таблиц, в которые лить, просто нет.

**Учётные записи сотрудников** лежат в схеме `auth`, которой управляет сам
Supabase; переносить её между проектами кустарно не стоит. Быстрее и надёжнее
завести людей заново в Настройки → Сотрудники — их несколько человек, а роли
и привязка к ЖК настраиваются в программе за минуту.

## Проверка, что всё встало

1. Открыть `/login`. Если вместо формы экран «Supabase не настроен» —
   переменные не подхватились (на Vercel после их добавления нужен **Redeploy**:
   они читаются на сборке, а не на лету).
2. Войти.
3. Дашборд **без красной плашки** «не удалось посчитать статистику» — значит
   функции на месте и схема `crm` открыта в Exposed schemas.
4. Открыть любой дом — шахматка рисуется, значит права на таблицы выданы.
5. Настройки → **SMS-напоминания**: панель внизу сама перечислит, чего не
   хватает — ключа шлюза, имени отправителя, `CRON_SECRET`, либо ключ
   service_role от другого проекта.
