# База данных — порядок установки

Всё выполняется в **Supabase → SQL Editor** (открыть файл на GitHub → кнопка
**Raw** → выделить всё → скопировать → вставить → **Run**).

## Новая база (с нуля) — ОДИН файл

Выполните только `000_full_setup.sql` — это все миграции, склеенные в
правильном порядке. Больше ничего запускать не нужно.

После него:
1. Authentication → Users → **Add user** → первый пользователь (Auto Confirm);
2. **готово — первый пользователь сам станет админом**;
3. Authentication → Sign In / Providers → **Allow new users to sign up → OFF**.

Файл генерируется из миграций ниже — по отдельности их запускают только
при обновлении существующей базы.

## Почему нет файлов 014–019

Раньше они существовали по отдельности, но **все падали с одной и той же
ошибкой** (`column "status" is of type object_status but expression is of type
text`), поэтому автостатусы квартир никогда не устанавливались. Ошибка
исправлена, а сами файлы объединены в один — `020_apply_all_pending.sql`. Он
содержит всё, что было в 014–019. Две параллельные инструкции («запусти 014,
потом 015…» и «запусти 020») только путали, поэтому осталась одна.

## Что делает какой файл

| Файл  | Назначение |
|-------|------------|
| `schema.sql`, `002`–`013` | Таблицы, типы, базовые политики доступа |
| `020` | Приём платежей, автостатус квартир, журнал удалений, защита от двойной брони, ограничение загрузки файлов, настройки — только админу |
| `021` | Роли (менеджер видит только свои ЖК, директор — только чтение), бронь без клиента, журнал создания/изменений |
| `022` | Пользователь без назначенной роли не видит и не может ничего — закрывает доступ самозарегистрированным |
| `023` | Каскадное удаление клиента админом (клиент + договоры + платежи, с записью в журнал) |
| `024` | Индексы для скорости (списки, поиск, шахматка, журнал) |
| `025` | Запрет нулевых/отрицательных платежей (RPC + ограничение таблицы) |
| `026` | Название и логотип компании на странице входа |
| `027` | Первый созданный пользователь автоматически становится админом |
| `028` | Список сотрудников и выдача ролей без service-ключа |
| `029` | Готовый аккаунт админа: admin@crm.tj / Admin12345 |
| `030` | Продажи по менеджерам (кто оформил сделку) + отчёт на дашборде |

## Переменные окружения

Смотри `.env.local.example` в корне проекта. Отдельно обрати внимание на
`SUPABASE_SERVICE_ROLE_KEY` — без него нельзя создавать учётные записи
сотрудников.

## Обязательная настройка в Dashboard

Authentication → Sign In / Providers → **Allow new users to sign up → OFF**.
Аккаунты сотрудников создаёт только админ на странице «Сотрудники».
